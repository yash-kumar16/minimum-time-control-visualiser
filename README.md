# Minimum-Time Optimal Control — Interactive Phase-Plane Lab

**Independent educational implementation · HTML, CSS, JavaScript · research interest: continuous-time optimal control**

A self-contained visualiser for the bounded-control, linear second-order system

\[
\dot x_1=x_2,\qquad \dot x_2=b x_1+a x_2+u(t),\qquad |u(t)|\le 1.
\]

The user can change `a` and `b`, inspect the eigenstructure and constant-control trajectories, display candidate switching curves and explore a numerically constructed bang-bang path from a chosen initial condition. All source code is in [`index.html`](index.html); no server, external packages or account are required.

## Run

Download the repository and open `index.html` in a modern browser. Alternatively run `python -m http.server 8000` and open `http://localhost:8000`. The control inputs and canvas are interactive.

Run small spectral/classification unit tests with `node --test tests/spectral.test.cjs` (Node.js 18+). These test the eigenvalue calculations but do not validate global time optimality.

## Mathematical construction

1. With `z=(x_1,x_2)^T`, write `\dot z=Az+Bu`, where `A=[[0,1],[b,a]]`, `B=[0,1]^T`.
2. For fixed `u in {-1,+1}`, when `b != 0` the rest point is `z_u=(-u/b,0)`. The eigenvalues are `lambda_±=(a ± sqrt(a²+4b))/2`; real and complex cases are treated separately.
3. Exact *constant-input* solution curves are sampled from exponential/eigenmode formulae, including focus/centre examples. This is not a generic numerical ODE integration of the plant.
4. Candidate terminal arcs are generated by integrating the fixed-input dynamics **backwards from the origin**. These appear as green switching curves.
5. For a clicked point, the app samples each fixed-input forward trajectory and selects an approximate close approach to the opposite terminal curve. This provides a **heuristic visual candidate**, **not** a proof of minimality or even an exact boundary-value solution.
6. The coloured reachable/controllable-region overlays are pedagogical geometric sketches based on the spectral classification, **not certified reachable sets for arbitrary parameters and finite horizons**.

This is a classical finite-dimensional control example. It does **not** implement an adjoint optimality solver, verify Pontryagin transversality, or prove that the displayed path has minimum time. Nontrivial boundary cases can be misclassified or missed by the distance threshold and finite time-search window.

## What to try

- Compare a stable node (`a=-3,b=-2`) with a saddle (`a=-1,b=6`): why does stability affect the geometry of candidates?
- Contrast a centre (`a=0,b=-4`) and a stable focus (`a=-1,b=-2`): periodic vs. decaying constant-control trajectories.
- Check how the switching-curve geometry changes as `a²+4b` crosses zero; the repeated-eigenvalue case currently uses a **small perturbation approximation** rather than a Jordan-form formula.
- Use the app to form **conjectures** about switching, then verify the corresponding problem analytically or with a separate shooting/optimal-control solver.

## Caveats that matter to researchers

- `b=0` is deliberately not supported by the present visualiser, even though some `b=0` systems (notably the double integrator) have standard minimum-time solutions.
- A numerical near-intersection can be a false positive. `No path found within search window` is **not** a proof of uncontrollability.
- The plotted controls are piecewise constant ±1; alternative feasible policies, extra switches, and singular structures are not exhaustively searched.
- The app is therefore a **control-theory teaching and hypothesis-generation tool**, not a validated optimal-control package.

## Why this project connects to the mathematical-biology research

For drug dosing the control constraints often take the form `0 <= u(t) <= u_max`, and the state can have multiple timescales (drug transport, intracellular response, proliferating/quiescent switching). This visualiser demonstrates familiarity with bounded controls and qualitative dynamics. Extending such geometric intuition to PDE or stochastic population control requires new mathematics; **it is not already implemented here**.
